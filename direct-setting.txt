================================================================================
直接设置 false 与未设置的区别 —— flagctl diff / unset 流程说明
================================================================================

本文只整理一条流程：用 `diff` 看出两个环境在“直接设置”上的差异，用
`unset` 撤销某环境的直接设置，并说明撤销前后环境配置状态的实际含义。
不改动任何公开命令、输出协议或 SQLite 数据格式；以下结论均可与
flagctl.py 现有函数逐一核对（函数名见各节括注与文末对照表）。

本文给出的样例结果是依据当前源码推导出的**可验证预期**，供手动执行
核对；不宣称这些命令已经被执行或已经实测通过。

--------------------------------------------------------------------------------
1. 核心结论：false 是有效设置，未设置就是“没有这条记录”
--------------------------------------------------------------------------------

* 开关只有两种**已设置**值：严格的文本 `true` 与 `false`（cmd_set 写入，
  parse_bool 校验）。`false` 与 `true` 地位完全相同，都是一行真实存在的
  记录（flags 表中 (env, key) 主键对应的一行），表示该环境被**显式关闭**。
* “未设置”不是一个值，而是该 (env, key) **没有记录**：可能从未 set，也
  可能已被 unset 删除。读取时 cmd_get 报 VALUE_NOT_SET；列举时 cmd_list
  的结果里根本不包含该键。
* **当前没有默认值，也没有任何环境间继承。** 未设置不会被解释成 false，
  也不会回退到其他环境；它只代表“本环境没有直接设置”，仅此而已。
* 因此 `false` 与未设置是两种不同的实际配置状态，diff 必须把它们区分开
  （cmd_diff）：
    - 一侧有布尔值、另一侧没有记录 → 输出该键，有值一侧是 JSON 布尔值，
      没有记录一侧是 null；
    - false 与未设置**不相等**，会作为差异输出；
    - 两侧布尔值相同（都为 true 或都为 false）→ 不输出该键；
    - 两侧都未设置 → 不输出该键；
    - 所有已知键都不构成差异时，整体结果为 `{}`。

--------------------------------------------------------------------------------
2. 固定样例
--------------------------------------------------------------------------------

前置状态（整个样例期间保持）：

* 数据库文件所在的**父目录存在**；
* demo.sqlite 是一个有效的 SQLite 库且含 flags 表；
* 其中**仅有一行**记录：env=`dev`, key=`new_ui`, value=严格文本 `false`；
* 环境 `qa` 在 flags 表中**没有任何记录**（对 new_ui 而言即未设置）。

即 dev 的 new_ui 被显式设置为 false，qa 的 new_ui 未设置。

--------------------------------------------------------------------------------
3. 完整流程：先 diff，再 unset，再复查
--------------------------------------------------------------------------------

步骤一：比较 dev（左）与 qa（右）

    输入（单行命令）：
        python flagctl.py --db demo.sqlite diff dev qa

    预期 stdout（单行 JSON，末尾换行；空格写法见第 4 节）：
        {"new_ui":{"left":false,"right":null}}

    预期：退出码 0，stderr 为空。

    含义（cmd_diff，左右由**参数顺序**确定，第一个参数是 left）：
    * `left: false` —— dev 有直接设置，值为布尔 false（显式关闭，是有效值）；
    * `right: null` —— qa 没有记录，null 只表示“比较的这一侧未设置”，
      它不是一个被保存的开关值，库里不存在文本 "null"；
    * 因为 false ≠ 未设置，new_ui 构成差异，被输出。

步骤二：撤销 dev 对 new_ui 的直接设置

    输入：
        python flagctl.py --db demo.sqlite unset dev new_ui

    预期 stdout：
        unset

    预期：退出码 0，stderr 为空；目标记录被**物理删除**（cmd_unset 执行
    DELETE，按 (env, key) 主键删除该行），而不是把值改写成 false。删除后
    dev 的 new_ui 即变为未设置状态。

步骤三：对同一库复查（此时 dev、qa 均无 new_ui 记录）

    输入：
        python flagctl.py --db demo.sqlite diff dev qa
    预期 stdout：
        {}
    说明：两侧都未设置，无差异（cmd_diff → cmd_list 两侧均为空映射）。

    输入：
        python flagctl.py --db demo.sqlite get dev new_ui
    预期：stdout 为空，stderr 只有一行 `VALUE_NOT_SET`，退出码 2
    （cmd_get 查不到目标记录即报 VALUE_NOT_SET）。

    输入：
        python flagctl.py --db demo.sqlite list dev
    预期 stdout：
        {}
    说明：list 把“该环境没有任何直接设置”表达为空对象，而不是错误
    （cmd_list）。

--------------------------------------------------------------------------------
4. 输出协议（成功与业务错误）
--------------------------------------------------------------------------------

成功（main 中的正常分支）：
    * 退出码为 0；
    * stderr 为空；
    * stdout 为单行结果加一个换行（`结果\n`）。
    * diff / list 的结果是 JSON 对象：键为键名，diff 的值形如
      {"left": ..., "right": ...}，已设置为 JSON 布尔 true/false，未设置
      为 null；list 的值为 JSON 布尔；没有内容时为 `{}`。
    * unset 成功输出文本 `unset`；get/set 成功输出严格文本 true/false。

业务或存储错误（FlagError，main 的 except 分支）：
    * 退出码为 2；
    * stdout 为空；
    * stderr 仅为错误码加一个换行（如 `VALUE_NOT_SET\n`），不含原值、
      堆栈或其他说明。

JSON 空格不影响含义：预期结果写作紧凑形式
`{"new_ui":{"left":false,"right":null}}` 仅为表达方便；当前实现用
json.dumps 序列化，实际在 `,` 与 `:` 后可能带空格，例如
`{"new_ui": {"left": false, "right": null}}`。二者是同一个 JSON 值，
逐字节比对时应先做 JSON 解析，而不是字符串比较。

--------------------------------------------------------------------------------
5. 环境名与键名规则
--------------------------------------------------------------------------------

环境名（normalize_env / validate_env）：
    * 先去除**两端**空白（strip），内部空格保留；因此 `" dev "` 与 `dev`
      指向同一环境，而 `"a b"` 不会变成 `"ab"`。
    * 区分大小写：`dev`、`Dev`、`DEV` 是不同环境。
    * diff 的两个环境名**分别**去除两端空白后，任一个为空或原本全是空白，
      都在访问存储之前报 EMPTY_ENV（退出码 2）。即 `diff "" qa`、
      `diff "   " qa`、`diff dev "  "` 均报 EMPTY_ENV。

键名（validate_key）：
    * 只接受已知键（当前为 new_ui）。
    * 对 unset 一个未知键，报 UNKNOWN_KEY（退出码 2），且该校验先于存储
      访问，不会改动数据库。

--------------------------------------------------------------------------------
6. 存储状态分类与边界（open_flag_store 统一维护，get/unset/list/diff 共用）
--------------------------------------------------------------------------------

不补建、不修复：除 set 外，读取与撤销流程**不会**创建缺失的数据库文件、
父目录或 flags 表，也不会改写异常数据。

(1) 父目录存在，但数据库文件缺失：
    * unset 报 VALUE_NOT_SET（没有可删除的记录），退出码 2；
    * diff 返回 `{}`（两侧都按“没有任何直接设置”处理），退出码 0；
    * 不会因此新建数据库文件。

(2) 文件是有效 SQLite 库，但缺少 flags 表：
    * unset 报 VALUE_NOT_SET，退出码 2；
    * diff 返回 `{}`，退出码 0；
    * 不会补建 flags 表。

(3) 以下情况报 STORAGE_ERROR（退出码 2）：
    * 数据库文件的父目录不存在；
    * 目标文件不是有效的 SQLite 数据库（连接/查询失败）；
    * flags 表存在但查询所需的列缺失（如缺少 env/key/value），或发生其他
      SQLite 错误。

(4) 已存在记录的值校验（严格文本 true / false）：
    * 对 diff：**目标两个环境中**任一**已知键**存有严格文本 `true`、
      `false` 以外的值（如 "maybe"、"FALSE"、"1"、空串等），即报
      STORAGE_ERROR，**不输出任何部分差异**（不是只跳过坏键）。
    * 未知键的记录不参与比较，其值即使异常也不影响 diff 结果；
    * 不在 diff 目标两个环境内的**其他环境**的异常值也不影响本次比较；
    * get 同理：仅当目标记录存在且值不是严格 true/false 时报
      STORAGE_ERROR，不做大小写转换、不去空白、不回显原值。

--------------------------------------------------------------------------------
7. 只读与删除语义（再次强调）
--------------------------------------------------------------------------------

* diff 是**只读**操作（cmd_diff 仅调用 cmd_list 做 SELECT），不创建任何
  文件或表，不增加、修改或删除记录。
* unset 是**删除**操作（cmd_unset 执行 DELETE）：它把直接设置的那一行删
  掉，使该键回到未设置状态；**不会**把值改成 false。false 只能通过
  set ... false 显式写入。
* 因此第 3 节中 unset 之后 diff 从 `{"new_ui":{"left":false,"right":null}}`
  变为 `{}`，不是因为两侧“都等于 false”，而是因为左侧记录已被删除、两侧
  都变成未设置。

--------------------------------------------------------------------------------
8. 兼容性
--------------------------------------------------------------------------------

本次仅新增本说明文档，不改变：
    * 公开命令：set / get / unset / list / diff 及 `--db` 参数与参数顺序；
    * 输出协议：成功退出码 0（stdout 单行结果 + 换行），业务错误退出码 2
      （stdout 空、stderr 错误码 + 换行）；
    * SQLite 数据：flags(env TEXT, key TEXT, value TEXT,
      PRIMARY KEY(env, key))，值为严格文本 "true"/"false"，旧库可直接使用。

--------------------------------------------------------------------------------
附：关键结论与函数对照（便于与源码核对）
--------------------------------------------------------------------------------

    环境名去两端空白、区分大小写 ........... normalize_env
    空/全空白环境名报 EMPTY_ENV ............ validate_env（main 中调用）
    未知键报 UNKNOWN_KEY ................... validate_key
    仅接受严格文本 true/false .............. parse_bool
    存储状态分类、不补建文件/表 ............ open_flag_store
    写入直接设置（含 false） ............... cmd_set
    查不到记录报 VALUE_NOT_SET、坏值报错 ... cmd_get
    删除记录（而非改成 false） ............. cmd_unset
    环境为空映射、未知键不出现 ............. cmd_list
    按参数顺序定左右、false≠null、同值省略 . cmd_diff
    退出码/stdout/stderr/JSON 序列化 ....... main
